## The RSA cryptosystem

The RSA cryptosystem, introduced by Rivest, Shamir and Adleman in 1978, is based on
the difficulty of factoring large numbers. It works as follows. Choose two random
150-digit primes $p$ and $q$, and compute $n = pq$ and
$\varphi(n) = m = (p-1)(q-1)$, where $\varphi$ is the Euler φ-function. Choose a
random $E$ with $\gcd(E, m) = 1$, and use the Euclidean algorithm to find $D$ with
$DE \equiv 1 \pmod{m}$. The numbers $n$ and $E$ are made public.

To send Alice the message piece $x$ (a positive integer less than $n$), Bob forms
$y = x^E \bmod n$. Alice recovers $x$ by computing $y^D \bmod n$; only Alice knows
$D$.

**The worked example.** With $p = 23$, $q = 29$: $n = pq = 667$ and
$\varphi(n) = m = (p-1)(q-1) = 616$. Take $E = 487$, since $\gcd(616, 487) = 1$. The
message 25 encodes as $25^{487} \bmod 667 = 169$, a computation done by the method of
repeated squares of §4.3. Using the Euclidean algorithm, $191 E = 1 + 151 m$, so the
decrypting key is $(n, D) = (667, 191)$, and the original message comes back as
$169^{191} \bmod 667 = 25$.

## Why RSA works

We know that $DE \equiv 1 \pmod{m}$; hence there exists a $k$ such that
$DE = km + 1 = k\varphi(n) + 1$. There are two cases. Assume first that
$\gcd(x, n) = 1$. Then by Theorem 6.16,
$$y^D = (x^E)^D = x^{DE} = x^{km+1} = (x^{\varphi(n)})^k x = (1)^k x = x \bmod n,$$
so Alice recovers the original message $x$.

That chain is a statement about **group exponents**: if $x$ raised to the group's size
is the identity, then $x$ raised to one more than any multiple of that size is $x$
again. It holds in any group, and RSA is what it says when the group is $U(n)$ —
where the size is $\varphi(n)$ and the identity is 1.

```2b4m
// power(g, k·m + 1) = g, given power(g, m) = e. This IS Judson's
// x^{km+1} = (x^m)^k · x = e^k · x = x, with `powerMul`, `powerAdd` and `powerOne`
// doing the three steps.
theorem anExponentOneAboveAMultipleOfTheOrderIsTheIdentityMap: forall g: Grp; forall m: Int; forall k: Int;
  power(g, m) = E -> power(g, integer.add(integer.mul(k, m), integer.succ(integer.ZERO))) = g
proof
  @generalize-g |
    fix g: Grp {
      @generalize-m |
        fix m: Int {
          @generalize-k |
            fix k: Int {
              @given-order-exponent |
                assume power(g, m) = E {
                  @power-at-m-is-identity |
                    power(g, m) = E
                    [by hypothesis given-order-exponent]
                  // (g^m)^k = g^(m·k), and the base is E, so the whole block collapses
                  @block-splits |
                    power(power(g, m), k) = power(g, integer.mul(m, k))
                    [using specialize group_power.powerMul(g, m, k)]
                  @identity-to-the-k |
                    power(E, k) = E
                    [using specialize group_power.powerOfIdentity(k)]
                  @block-at-identity |
                    power(E, k) = power(g, integer.mul(m, k))
                    [by rewrite power-at-m-is-identity block-splits]
                  @block-is-identity |
                    E = power(g, integer.mul(m, k))
                    [by rewrite identity-to-the-k block-at-identity]
                  // g^(m·k) · g^1 = g^(m·k + 1), and the left factor is E
                  @exponents-add |
                    op(power(g, integer.mul(m, k)), power(g, integer.succ(integer.ZERO)))
                      = power(g, integer.add(integer.mul(m, k), integer.succ(integer.ZERO)))
                    [using specialize group_power.powerAdd(g, integer.mul(m, k), integer.succ(integer.ZERO))]
                  @power-one-is-g |
                    power(g, integer.succ(integer.ZERO)) = g
                    [using specialize group_power.powerOne(g)]
                  @product-with-g |
                    op(power(g, integer.mul(m, k)), g)
                      = power(g, integer.add(integer.mul(m, k), integer.succ(integer.ZERO)))
                    [by rewrite power-one-is-g exponents-add]
                  @identity-times-g |
                    op(E, g) = power(g, integer.add(integer.mul(m, k), integer.succ(integer.ZERO)))
                    [by rewrite block-is-identity product-with-g]
                  @identity-left |
                    op(E, g) = g
                    [using specialize group.opIdentityLeft(g)]
                  @round-trip-at-m-times-k |
                    g = power(g, integer.add(integer.mul(m, k), integer.succ(integer.ZERO)))
                    [by rewrite identity-left identity-times-g]
                  // the book writes the multiple as k·m; commute to match
                  @commuted |
                    integer.mul(k, m) = integer.mul(m, k)
                    [using specialize integer.mulIsCommutative(k, m)]
                  @round-trip |
                    g = power(g, integer.add(integer.mul(k, m), integer.succ(integer.ZERO)))
                    [by rewrite commuted round-trip-at-m-times-k]
                  @conclusion-round-trip |
                    power(g, integer.add(integer.mul(k, m), integer.succ(integer.ZERO))) = g
                    [by symmetry round-trip]
                }
              @order-implies |
                power(g, m) = E -> power(g, integer.add(integer.mul(k, m), integer.succ(integer.ZERO))) = g
                [by discharge given-order-exponent]
            }
          @discharge-k |
            forall k: Int; power(g, m) = E -> power(g, integer.add(integer.mul(k, m), integer.succ(integer.ZERO))) = g
            [by generalize generalize-k]
        }
      @discharge-m |
        forall m: Int; forall k: Int; power(g, m) = E -> power(g, integer.add(integer.mul(k, m), integer.succ(integer.ZERO))) = g
        [by generalize generalize-m]
    }
  @conclusion |
    forall g: Grp; forall m: Int; forall k: Int;
      power(g, m) = E -> power(g, integer.add(integer.mul(k, m), integer.succ(integer.ZERO))) = g
    [by generalize generalize-g]
qed
```

**The second case.** Assume now that $\gcd(x, n) \neq 1$. Since $n = pq$ and
$x < n$, we know $x$ is a multiple of $p$ or a multiple of $q$, but not both; we
describe the first possibility only, the second being entirely similar. There is then
an integer $r$, with $r < q$ and $x = rp$. Note that $\gcd(x, q) = 1$ and that
$m = \varphi(n) = (p-1)(q-1) = \varphi(p)\varphi(q)$. Then, by Theorem 6.16 but now
mod $q$,
$$x^{km} = x^{k\varphi(p)\varphi(q)} = (x^{\varphi(q)})^{k\varphi(p)} =
(1)^{k\varphi(p)} = 1 \bmod q,$$
so there is an integer $t$ with $x^{km} = 1 + tq$. Thus Alice recovers the message in
this case too:
$$y^D = x^{km+1} = x^{km} x = (1 + tq)x = x + tq(rp) = x + trn = x \bmod n.$$

> *This second case is not a statement about group exponents — it turns on $n$'s
> factorization as $pq$, the bound $x < n$, and the Chinese Remainder Theorem, none of
> which are available. So the case transcribed above is the unit case, which is the one
> the chapter computes with.*

Breaking RSA means finding $D$ from $n$ and $E$, for which it suffices to factor $n$
and run the Euclidean algorithm; had we known that $667 = 23 \cdot 29$ in the example
above, we could have recovered $D$.

## Message verification

There is a problem of message verification in public key cryptosystems: since the
encoding key is public, anyone can send an encoded message. Suppose Bob's keys are
$(n', E')$ and $(n', D')$, and Alice's are $(n, E)$ and $(n, D)$. Before sending $x$,
Bob *decrypts* it with his own key, $x' = x^{D'} \bmod n'$. Anyone can turn $x'$ back
into $x$ by encryption with Bob's public $E'$ — but only Bob could have formed $x'$,
which is what authenticates it.

The mathematics is the same round trip as above, run in the other order: the signature
verifies because $D'$ and $E'$ compose to one more than a multiple of the group's size,
whichever way round they are applied.
