# Private Key Cryptography

A literate `2b4m` transliteration of **Chapter 7 ("Introduction to Cryptography"),
§7.1 "Private Key Cryptography"** of Thomas W. Judson's *Abstract Algebra: Theory and
Applications* (source: `vendor/aata/src/crypt.xml`, lines 67–250; © 1997–2026 Judson,
GFDL 1.3). Run `2b4m check aata/7.1-private-key-cryptography.md` to verify.

Chapter 7 is an *application* chapter: most of its text is narrative — shift codes,
frequency analysis, Caesar's cipher — and only one result in §7.1 is a theorem. That
result is transliterated here; the worked examples are reproduced as prose.

## Single-key cryptosystems

In **single key** or **private key** cryptosystems the same key is used for both
encrypting and decrypting messages. To encrypt a plaintext message, we apply to the
message some function which is kept secret, say $f$. This function will yield an
encrypted message. Given the encrypted form of the message, we can recover the
original message by applying the inverse transformation $f^{-1}$. The transformation
$f$ must be relatively easy to compute, as must $f^{-1}$; however, $f$ must be
extremely difficult to guess from available examples of coded messages.

**The Caesar shift.** Digitize the alphabet by letting $\text{A} = 00$,
$\text{B} = 01, \ldots, \text{Z} = 25$. The encoding function is
$$f(p) = p + 3 \bmod 26,$$
so $A \mapsto D$, $B \mapsto E, \ldots, Z \mapsto C$. The decoding function is
$f^{-1}(p) = p - 3 \bmod 26 = p + 23 \bmod 26$. The encoded message DOJHEUD digitizes
to $3, 14, 9, 7, 4, 20, 3$; applying $f^{-1}$ gives $0, 11, 6, 4, 1, 17, 0$, or
ALGEBRA. There is nothing special about either 3 or 26.

**Cryptanalysis** is concerned with deciphering an intercepted message. Frequency
analysis often suffices against a shift: $\text{E} = 04$ is the most common letter in
English, so if $\text{S} = 18$ is the most common ciphertext letter, then
$18 = 4 + b \bmod 26$ and $b = 14$.

## The affine cryptosystem

Generalizing the shift, take
$$f(p) = ap + b \bmod 26.$$
Judson: *"We first need to find out when a decoding function $f^{-1}$ exists. Such a
decoding function exists when we can solve the equation $c = ap + b \bmod 26$ for $p$.
By Proposition 3.4, this is possible exactly when $a$ has an inverse or, equivalently,
when $\gcd(a, 26) = 1$. In this case $f^{-1}(p) = a^{-1}p - a^{-1}b \bmod 26$."* Such
a cryptosystem is called an **affine cryptosystem**.

That is the one theorem in §7.1, and it holds over $\mathbb{Z}_n$ for any modulus —
nothing depends on 26. "$a$ has an inverse" is `isUnit(a)`, which
`isUnitCharacterization` relates to the gcd condition; the inverse is `unitInverse(a)`.

Judson shows the algebra rather than asserting it, so the proof is transcribed here
step by step: distribute $a^{-1}$ over the ciphertext, collapse $a^{-1}a$ to 1, then
cancel the shift. (The same result is available as a reusable library theorem,
`mod_n.anAffineCipherWithAUnitMultiplierDecodes`; this is the book's derivation.)

```2b4m
import mod_n <<< "std/integer/mod-n.b4m"

sort Zn = mod_n.Zn
const ZERO = mod_n.ZERO
const ONE = mod_n.ONE
func add = mod_n.add
func mul = mod_n.mul
func neg = mod_n.neg
pred isUnit = mod_n.isUnit
func unitInverse = mod_n.unitInverse

// the ring laws Judson uses without comment
fact addAssoc = mod_n.addAssoc
fact addCommutes = mod_n.addCommutes
fact addIdentityRight = mod_n.addIdentityRight
fact addInverseLeft = mod_n.addInverseLeft
fact mulAssoc = mod_n.mulAssoc
fact mulDistribLeft = mod_n.mulDistribLeft
fact mulOneLeft = mod_n.mulOneLeft
fact unitInverseLeft = mod_n.unitInverseLeft

// "equivalently, gcd(a, 26) = 1" — the gcd condition IS unithood
fact isUnitCharacterization = mod_n.isUnitCharacterization

// f⁻¹(f(p)) = p, where f(p) = ap + b and f⁻¹(c) = a⁻¹c − a⁻¹b.
theorem affineDecodes: forall a: Zn; forall b: Zn; forall p: Zn;
  isUnit(a) ->
  add(mul(unitInverse(a), add(mul(a, p), b)), neg(mul(unitInverse(a), b))) = p
proof
  @generalize-a |
    fix a: Zn {
      @generalize-b |
        fix b: Zn {
          @generalize-p |
            fix p: Zn {
              @given-a-is-invertible |
                assume isUnit(a) {
                  @a-is-invertible |
                    isUnit(a)
                    [by hypothesis given-a-is-invertible]

                  // a⁻¹(ap + b) = a⁻¹(ap) + a⁻¹b
                  @decoder-distributes |
                    mul(unitInverse(a), add(mul(a, p), b))
                      = add(mul(unitInverse(a), mul(a, p)), mul(unitInverse(a), b))
                    [using specialize mulDistribLeft(unitInverse(a), mul(a, p), b)]

                  // a⁻¹(ap) = (a⁻¹a)p = 1·p = p
                  @regroup-the-multiplier |
                    mul(mul(unitInverse(a), a), p) = mul(unitInverse(a), mul(a, p))
                    [using specialize mulAssoc(unitInverse(a), a, p)]
                  @the-multiplier-cancels |
                    mul(unitInverse(a), a) = ONE
                    [using specialize unitInverseLeft(a) a-is-invertible]
                  @one-times-the-plaintext |
                    mul(ONE, p) = mul(unitInverse(a), mul(a, p))
                    [by rewrite the-multiplier-cancels regroup-the-multiplier]
                  @one-is-the-identity |
                    mul(ONE, p) = p
                    [using specialize mulOneLeft(p)]
                  @plaintext-recovered |
                    p = mul(unitInverse(a), mul(a, p))
                    [by rewrite one-is-the-identity one-times-the-plaintext]

                  // so the decoder's first term is p + a⁻¹b
                  @decoder-is-plaintext-plus-shift |
                    mul(unitInverse(a), add(mul(a, p), b))
                      = add(p, mul(unitInverse(a), b))
                    [by rewrite plaintext-recovered decoder-distributes]

                  // and subtracting a⁻¹b leaves p
                  @reassociate-the-shift |
                    add(add(p, mul(unitInverse(a), b)), neg(mul(unitInverse(a), b)))
                      = add(p, add(mul(unitInverse(a), b), neg(mul(unitInverse(a), b))))
                    [using specialize addAssoc(p, mul(unitInverse(a), b), neg(mul(unitInverse(a), b)))]
                  @shift-plus-its-negation-left |
                    add(neg(mul(unitInverse(a), b)), mul(unitInverse(a), b)) = ZERO
                    [using specialize addInverseLeft(mul(unitInverse(a), b))]
                  @shift-commutes |
                    add(mul(unitInverse(a), b), neg(mul(unitInverse(a), b)))
                      = add(neg(mul(unitInverse(a), b)), mul(unitInverse(a), b))
                    [using specialize addCommutes(mul(unitInverse(a), b), neg(mul(unitInverse(a), b)))]
                  @shift-cancels |
                    add(mul(unitInverse(a), b), neg(mul(unitInverse(a), b))) = ZERO
                    [using chain shift-commutes shift-plus-its-negation-left]
                  @shift-removed |
                    add(add(p, mul(unitInverse(a), b)), neg(mul(unitInverse(a), b)))
                      = add(p, ZERO)
                    [by rewrite shift-cancels reassociate-the-shift]
                  @plaintext-plus-zero |
                    add(p, ZERO) = p
                    [using specialize addIdentityRight(p)]
                  @shift-removed-leaves-the-plaintext |
                    add(add(p, mul(unitInverse(a), b)), neg(mul(unitInverse(a), b))) = p
                    [using chain shift-removed plaintext-plus-zero]

                  @conclusion-decodes |
                    add(mul(unitInverse(a), add(mul(a, p), b)), neg(mul(unitInverse(a), b))) = p
                    [by rewrite decoder-is-plaintext-plus-shift shift-removed-leaves-the-plaintext]
                }
              @invertible-implies-decodable |
                isUnit(a) ->
                  add(mul(unitInverse(a), add(mul(a, p), b)), neg(mul(unitInverse(a), b))) = p
                [by discharge given-a-is-invertible]
            }
          @discharge-p |
            forall p: Zn; isUnit(a) ->
              add(mul(unitInverse(a), add(mul(a, p), b)), neg(mul(unitInverse(a), b))) = p
            [by generalize generalize-p]
        }
      @discharge-b |
        forall b: Zn; forall p: Zn; isUnit(a) ->
          add(mul(unitInverse(a), add(mul(a, p), b)), neg(mul(unitInverse(a), b))) = p
        [by generalize generalize-b]
    }
  @conclusion |
    forall a: Zn; forall b: Zn; forall p: Zn;
      isUnit(a) ->
      add(mul(unitInverse(a), add(mul(a, p), b)), neg(mul(unitInverse(a), b))) = p
    [by generalize generalize-a]
qed
```

**The worked example.** For the affine cryptosystem to work we must choose an
$a \in \mathbb{Z}_{26}$ that is invertible, which needs $\gcd(a, 26) = 1$. Take
$a = 5$, so $a^{-1} = 21$, and encryption $f(p) = 5p + 3 \bmod 26$. Then ALGEBRA
encodes as $3, 6, 7, 23, 8, 10, 3$, or DGHXIKD, and
$f^{-1}(p) = 21p - 21 \cdot 3 = 21p + 15 \bmod 26$. These are concrete computations in
$\mathbb{Z}_{26}$; the general fact above is what makes them sound.

## Polyalphabetic cryptosystems

A cryptosystem would be more secure if a ciphertext letter could represent more than
one plaintext letter. Generalizing affine codes with matrices, store a pair of letters
in a vector $\mathbf{p}$, let $A$ be an invertible $2 \times 2$ matrix over
$\mathbb{Z}_{26}$, and encode by $f(\mathbf{p}) = A\mathbf{p} + \mathbf{b}$. The
decoding function is then $f^{-1}(\mathbf{p}) = A^{-1}\mathbf{p} - A^{-1}\mathbf{b}$ —
structurally the affine result one dimension up.

There is no matrix theory in `std`, so this is recorded as prose. The shape of the
argument is identical to the scalar case above: invertibility of the multiplier is
exactly what makes the decoder exist.
